Статус проставляется у каждой задачи в обоих планах и обновляется по мере работы.

| Метка | Значение |
|---|---|
| `[x]` | сделано и проверено (тест, сборка или ручная проверка) |
| `[~]` | сделано частично, в задаче написано что осталось |

## Связки прошивка ↔ приложение

Эти пары меняются вместе; старая прошивка 3.0.0 обязана работать с новым сервером.

| Приложение | Прошивка | Зачем |
|---|---|---|
| A0.4 — не слать устройству панельные события, транслит по Wi-Fi | F1.4 — фильтр не-ASCII, `LINK_CMD_MAX` 1024, счётчики дропов | Сейчас `tasks_snapshot` > 15 КБ рвёт сокет в цикле, кириллица даёт мусор в пузыре |
| B4.5 — темп TTS по часам, `audio_start{id}` | F1.6 — джиттер-буфер, `queued_ms` в статусе | Кольцо 48 КБ без PSRAM переполняется за ~9 с |
| W5.7 — `POST /api/device/command`, `DEVICE_ACTIONS` += `device_volume/set_autorotate/restart/status` | F2.9 — `proto: 4`, `rotation`, диагностика в `device_status` | Панель не может управлять устройством дальше поворота |
| W5.8 — `pet_name`, `ota_pass` в форме Wi-Fi | F2.5 — `containsKey` в конфиге | OTA-пароль никогда не приходит, OTA фактически выключен |
| B4.3 — `set_mic off/on` во время речи | уже умеет | Питомец слышит собственный хвост фразы |
| F3.3 — команда `ota{url}` | панель: кнопка «Обновить по Wi-Fi» | Без mDNS и пароля ArduinoOTA |

## Субагенты для работы над проектом

В `.claude/agents/` заведены пять типов (подхватываются при старте новой сессии):

| Агент | Для чего | Умеет запускать |
|---|---|---|
| `firmware-auditor` | прошивка, протокол, FreeRTOS, I2S | `pio run` (без upload) |
| `backend-auditor` | FastAPI, asyncio, инструменты, MCP, голос | `pytest`, `ruff` |
| `web-auditor` | React, стор, контракт WS/REST, ESP Web Tools | `vitest`, `tsc`, `oxlint` |
| `tray-packager` | pystray, PyInstaller, Inno Setup, пути | `build.ps1 -SkipInstaller` |
| `roadmap-planner` | сведение отчётов в план, проверка парных изменений протокола | только чтение |

Типовой сценарий: аудит слоя → задача из плана → `backend-auditor`/`firmware-auditor`
проверяет реализацию и тесты → `roadmap-planner` сверяет, что парная сторона протокола
не забыта.
