# План доработки прошивки

Пути относительно `firmware/src/`, серверные — относительно `backend/`. Приоритеты P0–P3,
трудоёмкость S (вечер), M (2–3 вечера), L (неделя+). Ссылки `файл:строка` — на рабочее
дерево 2026-09-07 (рефакторинг `AudioIO/Link/Motion`, версия 3.0.0).

## Цели и ограничения

- Железо: AtomS3R (ESP32-S3, 8 МБ PSRAM) + Atomic Echo Base (ES8311), экран GC9107 128×128,
  IMU, LTR-553, одна кнопка. Универсальная сборка `m5stack-atoms3` должна работать и на
  AtomS3 без PSRAM.
- Тулчейн: `espressif32@7.0.1` → Arduino-ESP32 2.0.17 на IDF 4.4, legacy I2S
  (`dma_buf_count=8×256`, `tx_desc_auto_clear=false`). WebSockets 2.7.3: блокирующий connect
  5 с, максимум кадра 15 КБ (больше — закрытие 1009), `malloc` на каждый кадр. Task-WDT 5 с
  с паникой, следит только за `IDLE0`.
- Что уже хорошо и не трогаем: кольцевой буфер SPSC с fence'ами (`AudioIO.cpp:85-129`),
  очереди микрофона и тонов, команды исполняются в `loop`, а не в задаче serial, микрофон
  читается всегда, Wi-Fi переподключается с backoff.
- Совместимость: сервер обязан работать с прошивкой 3.0.0. Новые поля протокола —
  необязательные, версия в `device_status.proto`.

## Этап F0 — Сначала сервер

Половина критичных проблем лечится на сервере (см. PLAN-app A0.4): не слать устройству
панельные события и микрофон браузера, транслитерировать `speak` по Wi-Fi, темповать TTS.
Делать до F1, иначе проверять прошивку по Wi-Fi бессмысленно: `tasks_snapshot` при каждом
подключении превышает 15 КБ и устройство живёт в цикле реконнекта.

## Этап F1 — Критичные баги (P0/P1, 3–4 дня)

### [ ] F1.1 Shake: одно событие на серию — S
`main.cpp:324-343`, `Motion.cpp:74-88`. Первый импульс ставит `_shaking`, следующий проход
`loop` (2 мс) уже шлёт `shake{count:1}` и делает `clearShake()`; через 220 мс дебаунса — снова.
Сервер на каждый пакет запускает TTS «Зачем трясёшь?» и `interrupt`. DIZZY (≥3) и PARTY (≥5)
недостижимы. Фронт-детектор был в `HEAD:main.cpp:388-401` и потерялся в рефакторинге.
Сделать: событие один раз по окончании серии (нет импульсов 500 мс или закрылось
`SHAKE_WINDOW_MS`) с итоговым count; `interrupt` не чаще раза в секунду; локальную эмоцию
показывать сразу.
Приёмка: пять быстрых встряхиваний → одно `shake{count:5}` и PARTY.

### [ ] F1.2 Render не должен морить IDLE0 — S
`main.cpp:438-453`, `Config.h:50,71`. `vTaskDelayUntil` при опоздании не блокирует; кадр
дольше 33 мс подряд (PARTY/HAPPY с анимированным фоном при `-Os`) → `IDLE0` без CPU 5 с →
WDT panic → перезагрузка. Сделать:
`if (xTaskDelayUntil(&wake, period) == pdFALSE) { wake = xTaskGetTickCount(); vTaskDelay(1); }`.
Добавить `frame_ms` в `device_status`. Кэшировать фон-градиент по эмоции (96 цветов при
смене, а не каждый кадр).
Приёмка: PARTY 5 минут без перезагрузки, `frame_ms` виден в панели.

### [ ] F1.3 Блокирующий connect в `loop` — S сейчас, M правильно
`Link.cpp:151` → `connect(host, port, 5000)` каждые ~9 с, пока сервер недоступен (ПК спит,
неверный IP в NVS). Кнопка и жесты мертвы по 5 с, очередь микрофона (4×32 мс)
переполняется, USB-fallback тоже стоит, потому что отправляет `loop`. Аналогично
`WiFiClient::write` при зависшем сокете держит до 10 с.
Быстро: `-D WEBSOCKETS_TCP_TIMEOUT=1500` в `build_flags` (макрос под `#ifndef`),
`setReconnectInterval` экспоненциально 4→30 с. Правильно — F3.1.
Приёмка: выключить сервер → кнопка отвечает, USB работает.

### [ ] F1.4 Команды: кириллица, лимит, парсер — S (пара с app A0.4)
- `PetAnimator` `showBubble`: отфильтровать байты ≥ 0x80 — шрифт без кириллицы, защита
  независимо от сервера.
- `LINK_CMD_MAX` 512 → 1024 (`Link.h:10`), зеркально `StaticJsonDocument<768>` → 1536
  (`main.cpp:165`). Сейчас `speak` длиннее ~250 символов по Wi-Fi выбрасывается целиком
  вместе с эмоцией.
- `deserializeJson(doc, (char*)payload)` — zero-copy, буфер из очереди писабельный.
- `main.cpp:179`: `if (!action) return;` — `{"action":5}` сейчас роняет прошивку.
- Счётчики `cmd_dropped`, `cmd_parse_err` в `device_status`.

### [ ] F1.5 Чужой звук не должен играть из питомца — сервер (app A0.4) + S
`Link.cpp:131-134` принимает любой бинарный кадр, включая микрофон браузера из
`PCMicTester`. На устройстве после появления `audio_start{id}` (F2.2) принимать только
поток текущего `id`.

### [ ] F1.6 Джиттер-буфер и `queued_ms` — M (пара с app B4.5)
`AudioIO.cpp:91-108, 229-236`, `Config.h:29`. Сервер льёт 1.16× реального времени; без PSRAM
кольцо 48 КБ переполняется за ~9 с, хвост фразы «проглатывается», `drop_out` растёт.
Сделать: старт воспроизведения при ≥200 мс в кольце; при опустошении — тишина до повторного
набора порога (сейчас фейд до нуля и старт со скачка — треск при джиттере); `queued_ms` в
`device_status`, и раз в секунду пока играет, чтобы сервер темповал.
Приёмка: монолог 30 с по Wi-Fi без выпадений, `drop_out = 0`.

### [ ] F1.7 AtomS3 без PSRAM: конфликт I2C — M
`AudioIO.cpp:24-25` `Wire.begin(38,39)` (I2C0) и M5Unified `In_I2C` (I2C1) на тех же пинах.
На AtomS3 IMU висит на этой же шине: после `Wire.begin` IMU молчит или каждый `M5.Imu.update()`
ждёт таймаут, замедляя `loop`. На AtomS3R не воспроизводится (там 45/0).
Сделать: для `board_M5AtomS3` — `M5.In_I2C.release()` перед `echobase.init` и
`sensors: false` в статусе; лучше — доступ к шине в `M5EchoBase.cpp:191-209` через колбэки,
чтобы кодек ходил через `M5.In_I2C`. Комментарий в `Config.h:13` уточнить.

## Этап F2 — Важные проблемы (P2, 3 дня)

### [ ] F2.1 Кнопка: HOLD по отпусканию — S
`Motion.cpp:118-123`, `main.cpp:299-317`. `wasHold()` срабатывает на 700 мс, поэтому чтобы
дойти до INFO (3 с) или перезагрузки (6 с), обязательно переключишь микрофон. HOLD (0.7–3 с)
и INFO (≥3 с) — по отпусканию; restart — при удержании ≥6 с с обратным отсчётом на экране.

### [ ] F2.2 Перебивание без хвоста — S
`AudioIO.cpp:131-138` чистит кольцо, но в приёмном буфере USB (16 КБ ≈ 0.45 с) и в TCP уже
лежат чанки. Окно «игнорировать входящее аудио» 300 мс после `stopPlayback`; с
`audio_start{id}` от сервера — отбрасывать кадры отменённого `id`.

### [ ] F2.3 TALKING без моргания — S
`main.cpp:514-531`: `PLAY_TAIL_MS=200` меньше пауз между предложениями (≥250 мс плюс синтез),
рот закрывается и открывается между фразами. Держать TALKING ≥800 мс после последнего блока
или до `agent_status idle`.

### [ ] F2.4 Сторож для `loop` — S
`esp_task_wdt_add(NULL)` в `setup` с таймаутом 15 с и `esp_task_wdt_reset()` в `loop`;
`render` тоже подписать и сбрасывать раз в кадр. Сейчас зависший `loop` снаружи не виден:
аудио и экран продолжают жить, питомец просто глохнет.

### [ ] F2.5 Конфиг по USB: только присутствующие ключи — S (пара с app W5.8)
`main.cpp:169-175`: `doc["pass"] | ""` затирает сохранённый пароль, если ключа нет; панель
не шлёт `ota_pass`, поэтому `enableOta` не вызывается никогда. Обновлять только ключи с
`containsKey`; принимать `pet_name`, `ota_pass`.

### [ ] F2.6 USB TX без блокировки — S
`Link.cpp:178-203`: если порт открыт процессом, который не читает (пауза сервера, чужой
монитор), каждый `Serial.write` блокирует до 30 мс, два кадра за проход → `loop` ~8 Гц.
Проверять `Serial.availableForWrite() >= 7 + bytes`, иначе дроп и счётчик; `setTxTimeoutMs(0)`.

### [ ] F2.7 NVS не роняет кадры микрофона — S
`Config.h:34` `MIC_CHUNK_SLOTS` 4 → 8 (+4 КБ); запись `Preferences` откладывать до
`!isRecording() && !isPlaying()`. Стирание страницы NVS занимает 100+ мс, а при legacy I2S без
`tx_desc_auto_clear` DMA на это время зацикливает последние 16 мс («жужжание»).

### [ ] F2.8 Мелочи — S
- `device` из `M5.getBoard()` вместо захардкоженного «AtomS3R» (`main.cpp:100`,
  `PetAnimator.cpp:533`).
- Часовой пояс от сервера (`set_time{tz,epoch}`) вместо `UTC+3` (`main.cpp:415`).
- `auto_brightness` сохранять в NVS.
- `AudioIO::begin` при частичном отказе освобождать уже выделенное.
- Комментарии в `Sensors.cpp:60` привести к реальным регистрам (`0x02` — 100 мс, не 50).

### [ ] F2.9 Протокол v4 — S (пара с app A0.4, W5.7)
- `device_status` += `proto: 4`, `rotation`, `autorotate`, `queued_ms`, `frame_ms`,
  `loop_hz`, `ws_reconnects`, `cmd_dropped`, `cmd_parse_err`.
- Прошивка шлёт `ping` раз в 20 с и считает RTT (сервер уже отвечает `pong`).
- `listening` и `pomodoro`: сервер не шлёт — убрать из прошивки или использовать
  `pomodoro` для кольца на экране (F4.6).
- Сервер: `DEVICE_ACTIONS` += `device_volume`, `set_autorotate`, `restart`, `status`.
- Новое событие от устройства `{"action":"wake"}` (F4.2).

## Этап F3 — Архитектура (P2, 4–5 дней)

### [ ] F3.1 Сетевая задача `net` — M
Всё, что может блокировать (WS `loop`, `sendBIN`, `ArduinoOTA.handle`, запись в USB), —
в задачу на ядре 0 с приоритетом 3; `loop` оставить кнопке, жестам, UI и разбору команд.
Очередь микрофона уже есть — `net` становится её потребителем. `WebSocketsClient` не
потокобезопасен: все вызовы только из `net`, команды в `loop` через существующую очередь.
Закрывает F1.3 полностью и делает F2.4 безопасным.

### [ ] F3.2 Энергопрофили — M
Сейчас `WiFi.setSleep(false)`, 30 fps всегда, CPU 240 МГц, подсветка гаснет только до трети.
Профиль «дремлет» (30–60 с без речи и касаний): `WIFI_PS_MIN_MODEM`, render 5–10 fps,
подсветка ниже, `setCpuFrequencyMhz(80)`. Профиль «активен» — мгновенно по любому событию.
IMU опрашивать 100 Гц вместо ~500 (`main.cpp:499`). I2S тактируется от PLL и смену частоты
CPU переживает, но проверить на слух обязательно.

### [ ] F3.3 OTA из панели — M
Команда `{"action":"ota","url":"http://<server>/firmware/firmware.bin"}` + `HTTPUpdate`
(сервер уже раздаёт `/firmware/*`); прогресс на экране; `render` и `audio_*` приостановить;
счётчик неудачных загрузок в NVS, после трёх — `esp_ota_set_boot_partition` на предыдущий
раздел (штатный rollback в Arduino-загрузчике выключен). Снимает зависимость от mDNS и
пароля ArduinoOTA. В панели — кнопка «Обновить по Wi-Fi» с версией из `manifest.json`
против `fw` из статуса.

### [ ] F3.4 Скрипты сборки — S
`copy_bins.py`: два env пишут в один каталог, манифест не знает, какой собран, — по записи
`builds` на env с суффиксом. `apply_env.py:33-38`: значения в кавычках или с пробелами ломают
`CPPDEFINES`. `.env` бэкендом не читается — ключи из `.env.example` убрать или подключить
`load_dotenv`.

- **F4.1 Barge-in голосом без AEC — M.** Сейчас во время речи микрофон закрыт

  коэффициент эха на BOOT-чайме; во время воспроизведения сравнивать RMS микрофона с

- **F4.2 Стук по столу = «слушаю» — S.** Двойной `wasTapped` → LISTENING локально +

- **F4.3 Жесты приближения и ночной режим — S.** Ладонь >1.5 с → часы/метрики; два взмаха →

- **F4.4 Кнопка без панели — S.** Тройной клик — принудительный USB/Wi-Fi; удержание 10 с —

- **F4.5 PSRAM — M.** WAV-сэмплы вместо синуса; кольцо последних 5 с микрофона («повтори,

## Целевая таблица протокола (v4)

Устройство → сервер: `device_status` (с новыми полями), `interrupt{reason}`,
`pet_touched{source}`, `shake{count}` (один раз на серию), `ping`, `wake` (новое),
бинарный PCM 1024 Б.

Сервер → устройство: `update_pc`, `speak`/`set_emotion` (транслит, ≤64 символов),
`agent_status`, `stop_audio`, `beep`, `set_rotation`, `set_screen`, `set_brightness`,
`set_mic`, `identify`, `device_volume`, `set_autorotate`, `restart`, `status`,
`set_time` (новое), `audio_start{id}` (новое), `ota{url}` (новое), `pong`, бинарный PCM
4096 Б (только при `audio_output` в `pet`/`both`).

Не уходит устройству: `tasks_snapshot`, `task_update`, `agent_step`, `voice_state`,
`user_speech*`, `device_status_update`, `approval_*`, `reminders_update`, `chat_reset`,
микрофон браузера.

USB-кадр `AA BB type len32 payload` совпадает с обеих сторон; серверный парсер читает по
два байта (`core/serial_manager.py:123-131`) и при потере одного байта ресинхронизируется
случайно — на сервере нужен побайтовый сканер (app B4.8).

## Риски

- `WEBSOCKETS_TCP_TIMEOUT` — проверить, что библиотека подхватывает макрос из `build_flags`.
- F3.1: любой вызов `WebSocketsClient` не из `net` — гонка. Держать дисциплину через
  единственную точку отправки.
- `efontJA_10` может не влезть с двумя OTA-разделами по 3.3 МБ — измерить до внедрения.
- F1.7: `In_I2C.release()` на AtomS3 отключает IMU совсем — жесты пропадут на этой плате,
  честно показывать в статусе.
- F3.2: снижение CPU до 80 МГц может задеть тайминги I2S DMA — тест на слух.

## Что не делаем

- Не переходим на IDF 5 / новый I2S API: пришлось бы переписать `M5EchoBase` и `AudioIO`,
  выгоды сейчас нет.
- Не делаем AEC: на S3 без ESP-SR ресурсов не хватит; энергетическая эвристика (F4.1)
  достаточна.
- Не добавляем BLE: делит радио с Wi-Fi, транспортов уже два.
