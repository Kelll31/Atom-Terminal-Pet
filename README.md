# Патрик — питомец-помощник программиста

Кибер-питомец, который живёт в M5Stack **AtomS3R + Atomic Echo Base**, слышит вас
через микрофон, отвечает голосом и **реально выполняет задачи на компьютере** —
через собственные инструменты и подключённые MCP-серверы.

```
   голос ──► VAD ──► распознавание ──► агент (LLM + инструменты + MCP) ──► действие
     ▲                                        │
     └──────── речь ◄── синтез ◄── ответ ◄────┘
                 │
              экран 128×128 с Патриком
```

## Что умеет

**Голос (живой режим)**
- Слушает непрерывно, речь выделяется детектором (VAD) с подстройкой под шум комнаты.
- Обращение по имени распознаётся нечётко: «Патрик», «а том», «адом», «атам» — всё считается обращением.
- После ответа диалог остаётся открытым (по умолчанию 45 секунд) — можно говорить дальше без имени.
- Питомца можно перебить: кнопкой на устройстве, встряской, кнопкой в панели, словом «стоп»,
  а если звук выводится на колонки ПК — то и просто голосом.
- Ответ произносится по предложениям, ещё пока модель договаривает.

**Действия на компьютере (29 встроенных инструментов + MCP)**
- Система: состояние ПК, процессы, завершение зависших, громкость, медиаклавиши, запуск программ,
  буфер обмена, активное окно.
- Файлы (только в разрешённых каталогах): просмотр, чтение, запись, поиск по имени и по содержимому.
- Разработка: выполнение команд в терминале, git status/diff, обзор проекта.
- Продуктивность: напоминания, помодоро, долговременная память о вас и проектах.
- Любые внешние **MCP-серверы** подключаются из панели в один клик.

**Безопасность**
- Три режима автономии: спрашивать всегда / разумный баланс / полное доверие.
- Опасные действия (запись файлов, команды, завершение процессов) требуют подтверждения в панели.
- Файловые операции ограничены списком каталогов, команды — списком запрещённых шаблонов.
- Все запуски инструментов пишутся в журнал `backend/logs/audit.jsonl`.

**Устройство**
- Патрик на экране: мимика под эмоцию, рот двигается в такт речи, взгляд следит за наклоном.
- Четыре экрана: мордочка, метрики ПК с графиком, часы с помодоро, состояние сети и датчиков.
- Кнопка: клик — погладить, двойной — сменить экран, удержание — выключить микрофон.
- Датчики: IMU (наклон, тряска, переворот), LTR-553 (приближение руки, автояркость экрана).

## Быстрый старт

```powershell
.\start.ps1
```
Скрипт создаст окружение, поставит зависимости и запустит сервер.
Панель откроется на [http://localhost:8000](http://localhost:8000).

Дальше в панели:
1. **Настройки** → выберите мозг и нажмите «Проверить связь»:
   - облако — пресет DeepSeek / OpenRouter / OpenAI и API-ключ;
   - локально — запустите LM Studio (Bionic) или Ollama, нажмите
     **«Найти локальную модель»**: адрес и модель подставятся сами, ключ не нужен.
2. **Настройки → Права** → добавьте рабочие каталоги, к которым питомцу можно обращаться.
3. **Прошивка** → прошейте AtomS3R прямо из браузера и передайте ему Wi-Fi по USB.
4. Скажите «Патрик, что грузит мой компьютер?» — или напишите то же самое в диалоге.

### Запуск вручную

```bash
cd backend && venv/Scripts/python.exe main.py    # сервер на :8000
cd web && npm run dev                            # панель на :5173 (для разработки)
```

```

```

## Прошивка

```bash
cd firmware
../backend/venv/Scripts/pio.exe run                    # сборка (универсальная)
../backend/venv/Scripts/pio.exe run -e m5stack-atoms3r # сборка с PSRAM для AtomS3R
../backend/venv/Scripts/pio.exe run -t upload          # заливка по USB
```

Собранные `.bin` автоматически копируются в `web/public/firmware` вместе с
манифестом, поэтому прошить можно и из браузера на вкладке «Прошивка»
(Chrome или Edge).

Перед заливкой освободите COM-порт: кнопка «Вернуть связь» на вкладке «Прошивка»
или запрос `POST /api/serial/disconnect`.

### Как устроена прошивка

Всё, что требует реального времени, разнесено по задачам FreeRTOS, и у каждого
ресурса ровно один владелец:

| Задача | Ядро | Что делает |
|---|---|---|
| `audio_tx` | 1 | пишет в динамик: речь из кольцевого буфера, в паузах — тишина |
| `audio_rx` | 1 | читает микрофон **всегда**, кадрами по 32 мс |
| `serial` | 1 | разбирает кадры USB и складывает команды в очередь |
| `render` | 0 | рисует кадр, единственный владелец шины дисплея |
| `loop()` | 1 | кнопка, жесты, команды, пересылка звука |

Микрофон читается даже во время ответа: кадры выбрасываются, но приёмный DMA
остаётся пустым. Иначе после реплики первые полсекунды записи — это собственный
голос питомца, и сервер принимал его за речь пользователя.

### Wi-Fi и секреты

`WIFI_PASS` из `.env` по умолчанию **не** попадает в прошивку. Собранный
`firmware.bin` лежит в репозитории и раздаётся панелью по HTTP, поэтому зашитый
в него пароль виден всем, у кого есть доступ к любому из двух. Штатный путь —
передать сеть по USB на вкладке «Прошивка», устройство сохранит её в NVS.

Для отладки поведение возвращается строкой `EMBED_WIFI=1` в `.env`.

### Обновление по воздуху

OTA включается, только если задан пароль (`ota_pass` в конфигурации, которую
панель отправляет по USB). Без пароля порт не открывается вовсе: открытый OTA
в локальной сети — это чужая прошивка в вашем питомце.

```bash
../backend/venv/Scripts/pio.exe run -t upload --upload-port atom-pet.local
```

## Окно панели

Из трея панель открывается в собственном окне приложения (pywebview поверх
системного WebView2) — без вкладок, адресной строки и чужих окон браузера.
Повторный клик по значку не плодит окна, а поднимает уже открытое.

Если WebView2 в системе нет, окно открывается через Edge в режиме приложения
(`--app=`), и только в крайнем случае — обычной вкладкой. Вернуть браузер можно
переключателем **Настройки → Программа → «Открывать в браузере»**.

## Обновление

Программа ставится поверх предыдущей версии: настройки, заметки и память
питомца лежат в `%LOCALAPPDATA%\AtomTerminalPet` и переустановку переживают.

Раз в сутки Патрик смотрит последний релиз репозитория и, если версия новее,
сообщает об этом. Обновиться можно двумя способами:

- **из трея** — пункт «Проверить обновления»: первый клик проверяет,
  второй скачивает и ставит;
- **из панели** — Настройки → Программа: там же видны версия, размер
  обновления и описание релиза.

Установщик скачивается во временный каталог, проверяется по sha256, ставится
тихо (`/SILENT`) и сам запускает Патрика обратно. Windows спросит подтверждение
прав: установщику они нужны для правила брандмауэра.

Выпуск новой версии — одной командой (нужен `gh`):

```powershell
powershell -ExecutionPolicy Bypass -File packaging\release.ps1 -Version 1.1.0
```

Скрипт запишет версию, соберёт установщик, посчитает sha256 и создаст черновик
релиза с приложенными файлами. Копия, запущенная из исходников, обновляется
через `git pull` — она об этом честно говорит.

## Локальная модель

Питомец умеет думать локально: LM Studio (в новых сборках называется **Bionic**),
Ollama, llama.cpp, Jan — всё это OpenAI-совместимые серверы, ключ им не нужен.

1. В LM Studio / Bionic: вкладка **Developer** → **Start Server** (по умолчанию порт 1234)
   и скачанная **чат-модель** (не эмбеддер!), желательно с поддержкой tool calling —
   без неё питомец сможет только разговаривать, но не действовать.
2. В панели: **Настройки → «Найти локальную модель»**. Сервер, адрес и модель
   подставятся сами; кнопка «Список моделей» перечитывает, что сейчас на сервере.
3. **«Проверить связь»** — заодно проверяет, умеет ли модель вызывать инструменты.

Адрес можно вписать и руками — схема и `/v1` дописываются сами:

| Программа | Base URL |
|---|---|
| LM Studio / Bionic | `http://127.0.0.1:1234/v1` |
| Ollama | `http://127.0.0.1:11434/v1` |
| llama.cpp / LocalAI | `http://127.0.0.1:8080/v1` |

Первый ответ локальной модели может идти минуту — сервер грузит веса в память,
поэтому таймаут для локальных адресов увеличен до 5 минут.

## Настройка голоса

| Параметр | Что делает |
|---|---|
| Живой диалог | Продолжение разговора без обращения по имени |
| Окно диалога | Сколько секунд после ответа действует живой режим |
| Пауза до конца фразы | Через сколько тишины фраза считается законченной |
| Чувствительность | Во сколько раз голос должен быть громче фона |
| Порог тишины | Абсолютный порог, если мешает шум вентиляторов |
| Перебивание | Разрешить прерывать питомца голосом |
| Движок | Vosk (офлайн) или Whisper API (точнее, нужен ключ) |

Модель Vosk для русского качается скриптом:
```bash
backend/venv/Scripts/python.exe backend/scripts/download_vosk_model.py
```

## Куда выводится звук

В настройках выбирается вывод: **питомец**, **колонки ПК** или **и то, и другое**.
Голосом перебивать можно, когда звук идёт на колонки ПК (иначе микрофон питомца
слышит прежде всего сам динамик) — в остальных случаях помогает кнопка на устройстве.

## Безопасность и приватность

- `backend/settings.json` с ключом **не коммитится** (см. `.gitignore`), шаблон — `settings.example.json`.
- Ключ можно задать переменной окружения `ATOM_API_KEY`, адрес модели — `ATOM_BASE_URL`
  (переменные среды, не `.env`: его читает только сборка прошивки).
- Распознавание речи по умолчанию офлайн (Vosk): звук не покидает компьютер.
  В облако уходит только текст запроса — и только к выбранной вами модели.
- С локальной моделью (LM Studio/Bionic, Ollama) не уходит и текст: всё остаётся на ПК.
  Облачный ключ на локальный сервер не отправляется — вместо него уходит заглушка.
